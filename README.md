# MediCare — Smart Hospital & Emergency Management System

## 1. Project Introduction

**MediCare** is a full-stack academic **Smart Hospital & Emergency Management System** designed to unify outpatient care, inpatient bed management, laboratory diagnostics, pharmacy FEFO batch dispensing, blood bank transfusion workflows, ambulance dispatch, and hospital billing with a dedicated **Emergency Ward & Signature Emergency Priority Engine**.

The application uses a **hybrid database architecture**:
- **MySQL / MariaDB (`medivault` schema, 3NF)** as the transactional relational system of record (34 base tables, 11 views, 4 triggers, 2 stored procedures).
- **MongoDB (`medivault` database)** for document-oriented diagnostic payloads (`lab_reports_raw`), immutable operational audit logs (`audit_log`), ambulance dispatch telemetry (`ambulance_dispatch_log`), and notification event logs (`notification_log`), with graceful degradation if MongoDB is offline.

> **Disclaimer**: MediCare is an academic software prototype. Triage acuity categories (`P1`–`P4`) and resource recommendations generated by the Emergency Priority Engine are illustrative software coordination aids, not a clinically validated triage protocol. All clinical assessment, diagnosis, and treatment decisions remain with authorized healthcare professionals.

## 2. Problem Statement & Project Objectives

### Problem Statement
Traditional hospital information systems often separate outpatient scheduling, inpatient bed tracking, pharmacy inventory, and emergency intake into disconnected silos. Common failure modes include:
- Double-booking doctors or hospital beds under concurrent staff requests.
- Partial saves when consultations and prescriptions are submitted in separate uncoordinated requests.
- Timezone date shifts (`UTC` vs `Asia/Kolkata` IST) causing appointments near midnight to display one day early.
- Unstructured or delayed coordination between emergency triage, on-duty physician shifts, and available emergency/ICU beds.

### Project Objectives
1. Enforce **Third Normal Form (3NF)** across all relational entities with single-column primary keys (`2NF` by construction) and row-level locking (`SELECT ... FOR UPDATE`) for concurrency-safe appointment booking, bed allocation, FEFO medicine batch deduction, and blood bank issuance.
2. Provide a **Signature Emergency Priority Engine** that evaluates patient triage priority (`P1`–`P4`), waiting duration, vital signs, presenting complaints, on-duty doctor shifts/leaves/workloads, and bed availability to recommend appropriate clinical resources for staff confirmation.
3. Guarantee **atomic clinical encounter saves** (consultation + medical record + optional inpatient admission request + prescription + lab requests) inside a single MySQL transaction with idempotent retry safety.
4. Maintain **timezone-safe date handling** (`dateStrings: ['DATE']` on the MySQL pool + local `YYYY-MM-DD` parsing in `mv-core.js`) across `TZ=Asia/Kolkata` and `TZ=UTC`.

## 3. Technology Stack

- **Frontend**: Vanilla HTML5, CSS3 (`medivault.css`, `medivault-restyle.css`, `clinical-record.css`), Vanilla JavaScript (`mv-core.js`, `mv-shell.js`, `reception-billing.js`, `dispense-record.js`), Bootstrap 5.3.3, Font Awesome 6.5.1, Lucide Icons, Chart.js.
- **Backend**: Node.js (v18+), Express.js (`^4.19.2`), `express-session` (`^1.18.0`), `express-async-errors` (`^3.1.1`), `bcryptjs` (`^2.4.3`), `dotenv` (`^16.4.5`).
- **Relational Database**: MariaDB 10.6+ / MySQL 8.0+ via `mysql2/promise` (`^3.10.0`).
- **Document Database**: MongoDB 6.0+ via `mongodb` (`^6.7.0`).

## 5. Installation, Environment Setup & Execution Instructions

```bash
# 1. Navigate to the application directory
cd project_backup/MediVault/06_Application

# 2. Create the MySQL / MariaDB database and load schema + seed data
mysql -u root -e "DROP DATABASE IF EXISTS medivault; CREATE DATABASE medivault CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root medivault < db/schema.sql
mysql -u root medivault < db/seed.sql

# 3. Configure environment variables
cp .env.example .env
# Edit .env and set SESSION_SECRET to a long random string:
# node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

# 4. Install dependencies and start the server
npm install
TZ=Asia/Kolkata npm start

# 5. Run the End-to-End Verification Suite & MongoDB Verification
TZ=Asia/Kolkata node test-e2e.js
TZ=UTC node test-e2e.js
node scripts/verify-mongo.js
```
